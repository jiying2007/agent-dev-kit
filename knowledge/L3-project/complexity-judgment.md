# 复杂度判断规则

> 来源: 企业级AI团队研发规范 (2026-05-13)
> 成熟度: verified

## 概述

按需求复杂度自动匹配流程强度，在"快"和"稳"之间找到最合适的平衡点。

## 三级复杂度

### Level 1: 简单任务

**特征**:
- 改文案、修 bug、小优化
- 影响范围 < 3 个文件
- 不涉及架构变更
- 时间预估 < 1 小时

**流程**:
```
需求 → 实现 → 验证
```

**产物**:
- 代码变更
- 简单说明

**适用场景**:
- 修复 typo
- 调整样式
- 小优化
- 配置修改

### Level 2: 中等任务

**特征**:
- 新功能、重构模块
- 影响范围 3-10 个文件
- 涉及模块级变更
- 时间预估 1-8 小时

**流程**:
```
需求 → 设计 → 任务 → 实现 → 测试 → 审查
```

**产物**:
- 需求文档
- 设计文档
- 任务清单
- 代码变更
- 测试报告
- 审查报告

**适用场景**:
- 新增功能
- 重构模块
- 接口变更
- 性能优化

### Level 3: 复杂任务

**特征**:
- 架构变更、跨模块改动
- 影响范围 > 10 个文件
- 涉及系统级变更
- 时间预估 > 8 小时

**流程**:
```
需求 → 设计 → 评审 → 任务 → 实现 → 测试 → 审查 → 集成 → 发布
```

**产物**:
- 需求文档
- 设计文档
- 评审报告
- 任务清单
- 代码变更
- 测试报告
- 审查报告
- 集成报告
- 发布报告

**适用场景**:
- 架构重构
- 跨模块改动
- 数据库变更
- API 重构

## 判断矩阵

| 维度 | Level 1 | Level 2 | Level 3 |
|------|---------|---------|---------|
| 文件数 | < 3 | 3-10 | > 10 |
| 架构影响 | 无 | 模块级 | 系统级 |
| 风险等级 | 低 | 中 | 高 |
| 时间预估 | < 1h | 1-8h | > 8h |
| 测试要求 | 简单验证 | 单元测试 | 完整测试 |
| 审查要求 | 可选 | 必需 | 严格 |

## 自动判断流程

### Spark 阶段

在 Spark 阶段自动判断复杂度：

1. **分析需求**: 理解要做什么
2. **评估影响**: 估算影响范围
3. **判断复杂度**: 根据判断矩阵确定级别
4. **选择流程**: 根据级别选择对应流程

### 判断命令

```bash
# 判断复杂度
adk complexity judge --requirement <file>

# 查看判断结果
adk complexity result --feature <name>
```

## 与 adk 的整合

### 与 Profile 整合

| 复杂度 | Profile | 流程 |
|--------|---------|------|
| Level 1 | core (快速模式) | Spark→Tasks→Build→Ship |
| Level 2 | core (标准模式) | 8 阶段生命周期 |
| Level 3 | release-hardening | 8 阶段+严格门禁 |

### 与 Gate 整合

| 复杂度 | Gate 要求 |
|--------|-----------|
| Level 1 | 基本验证 |
| Level 2 | 标准门禁 |
| Level 3 | 严格门禁 |
