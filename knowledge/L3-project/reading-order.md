# 分层阅读规则

> 来源: 企业级AI团队研发规范 (2026-05-13)
> 成熟度: verified

## 概述

不同项目类型，阅读顺序完全不同。正确阅读是正确实现的前提。

## 新项目（从零搭建）

**阅读顺序**:
```
README → AGENTS.md → CONTEXT.md → 项目结构 → 当前任务
```

**关注点**:
- 领域边界在哪
- 每个模块该干什么
- 命名统一不统一
- 整体设计是否清晰

**核心原则**: 先把结构和规范立住

## 老项目（维护/改造）

**阅读顺序**:
```
AGENTS.md → 现有代码 → 变更影响 → 当前任务
```

**关注点**:
- 千万别把现有系统改崩
- 理解现有约定
- 评估变更影响范围

**核心原则**: 先理解再动手

## 微型改动

**阅读顺序**:
```
相关文件 → 当前任务
```

**核心原则**: 最小阅读，快速执行

## 判断标准

| 场景 | 判断条件 | 阅读策略 |
|------|----------|----------|
| 新项目 | 项目创建 < 1 周 | 完整阅读 |
| 老项目 | 项目存在 > 1 周 | 先读 AGENTS.md |
| 微型改动 | 影响 < 3 个文件 | 最小阅读 |

## 与 adk 的整合

### Spark 阶段

在 Spark 阶段自动判断项目类型，选择阅读顺序：

1. 检查项目是否存在 > 1 周
2. 检查是否有 AGENTS.md
3. 根据判断选择阅读顺序

### 快速模式

微型改动可以直接跳过阅读阶段，进入快速模式。
