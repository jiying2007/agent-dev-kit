# 3.1.0-rc.2 Target Contract 迁移

## 适用范围

本文面向从 `3.1.0-rc.1` 或旧的 direct-target 输出迁移到 `3.1.0-rc.2` 的维护者。`rc.2` 仍是 prerelease；三个 direct target 均保持 `experimental`，真实运行时 discovery/load/trigger/permission 未认证前不得提升为 stable。

## 破坏性变化

| 项目 | rc.1 | rc.2 |
|---|---|---|
| Claude Code Skill | `skills/<name>.md` | `skills/<name>/SKILL.md` |
| OpenCode Agent | legacy `prompts → agent → <name>.md` tree | `agents/<name>.md` |
| OpenCode Skill | legacy `prompts → skill → <name>.md` tree | `skills/<name>/SKILL.md` |
| Hermes Skill | 缺少必需 description | `skills/<name>/SKILL.md`，包含 name/description |
| Hermes Agent | 可能产生非原生输出 | 明确 unsupported，exit 2 且不产生部分结果 |
| export/install | 两套渲染语义 | 共享同一 versioned TargetAdapter |
| install plan/receipt | v1/v2 | plan v2、receipt v3；v1 plan 拒绝，v1/v2 receipt 只读回滚 |
| symlink install | legacy 可选 | fail closed；仅 copy mode |

Skill 的 `references/`、`scripts/`、`assets/`、`templates/`、`examples/` 会保持目录结构复制；任何 symlink 都会在计划或导出前拒绝。

## 迁移步骤

1. 对旧 target 做独立备份，不在原目录上直接试验。
2. 执行 `target check --all --level static`，确认 contract 与全部 resolved assets 通过。
3. 使用新 CLI 生成 `install plan`，审查 `contract_sha256`、`active_receipt_sha256`、逐文件 source/rendered hash、mode、conflicts、UUID 与 expiry。
4. 若目标由 rc.1 安装，先用旧 receipt 回滚；本地 release rehearsal 会自动执行同等的 `rollback-before-install` 迁移。
5. apply rc.2 plan 后，用真实目标运行时分别执行 discovery、load、trigger、permission smoke；fixture smoke 只能证明 harness contract。
6. 若任一阶段失败，用 receipt v3 rollback；从 checksum 匹配的 rc.1 artifact 重装并比对 managed hashes，不得手工删除部分文件来伪造干净状态。

示例：

```bash
bash scripts/devkit.sh target check --all --level static --summary-json
bash scripts/devkit.sh install plan --tool claude-code --target /tmp/claude-native --profile core --mode copy --output /tmp/claude-plan.json
bash scripts/devkit.sh install apply --plan /tmp/claude-plan.json --summary-json
bash scripts/devkit.sh install rollback --receipt /tmp/claude-native/.adk-install-receipt.json --summary-json
```

## 回滚锚点

- 原始 rc.1 artifact 与 `.sha256` 必须保留。
- rc.2 receipt 的 digest、previous receipt、backup hashes 必须完整。
- release rehearsal 必须证明 candidate managed files 被全部移除；上一版本若先回滚，则必须从保留的 rc.1 artifact 重装并比对全部 managed hashes，随后再清理 rehearsal target。
- 不自动修改用户目录、tag、GitHub Release 或 `~/codex -> ~/.codex` live chain。

## 未完成认证

静态 contract、golden tree、fixture smoke、export/install hash equivalence 和本地升级回滚属于 source/test/local-runtime evidence。它们不能替代 Claude Code、OpenCode、Hermes 的真实运行时发现与触发证据，也不能解除双运行时 campaign、独立操作者或 30 天 field blocker。
