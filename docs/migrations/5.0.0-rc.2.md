# 5.0.0-rc.2 候选加固迁移

## 迁移范围

`5.0.0-rc.2` 延续 `rc.1` 的 5.x 平台控制面边界，并替换它作为当前候选身份。本次加固发布溯源、本地 CI receipt 和 `4.0.0` 升级诊断；不改写 `rc.1` 或 4.x 历史。

- release source distribution 默认必须来自 clean Git commit，并记录 commit、tree、dirty 状态和 source distribution SHA256。
- dirty 或非 Git source 只有显式 `--allow-unbound-snapshot` 才能构建，且固定标记 `release_eligible=false`，不能进入 rehearsal 或 publish。
- local-CI parity 使用稳定 source snapshot 和双 Python full receipt；同一 snapshot 可复用已核验结果，失败时仍保留有界日志尾部。
- `target_contract_missing` 只在精确 legacy bundle 边界迁移；不兼容或无效 target contract 继续 hard cut。

manifest 数据格式仍为 `schema_version: 4.0.0`；产品发布版本为 `5.0.0-rc.2`。

## 升级与验证

1. 保留官方 `4.0.0` artifact、checksum、receipt 和受管资产 hash；缺少任一项时只能做诊断演练，不能声明正式连续性通过。
2. 在 clean `rc.2` commit 上运行 strict validate、quick/full、release check 和 release build。
3. 核对 release manifest 的 `source_identity`、`source_distribution_sha256` 和 `release_eligible=true`。
4. 重新生成 5.x campaign plan、runtime smoke 与 owner attestation；旧候选绑定不能直接沿用。
5. tag、远端 Release、source-to-live 和 Software M5 field certification 仍需独立授权与证据。

## 回滚

候选回滚恢复完整 `4.0.0` 或上一已批准候选的 source/artifact/receipt/managed hashes。禁止用不可发布 snapshot 或局部文件拼接回滚锚点。
