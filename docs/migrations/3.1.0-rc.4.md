# 3.1.0-rc.4 外部实践吸收硬切迁移

## 适用范围

本迁移面向 `3.1.0-rc.3 -> 3.1.0-rc.4`。RC4 仍是 prerelease，不代表最终 `3.1.0`、Software M5 certification、远端 CI 或 runtime/field 认证。

## 破坏性变化

- 前代 intake Skill 已删除，不提供兼容别名或 warning wrapper；精确退役资产名只保留在 change/release provenance 中。
- 新入口由 `external-practice-curator`、optional Skill `adk-external-practice-absorption` 与 Workflow `external-practice-absorption` 组成。
- `research-intake` profile 默认包含 curator 及审查角色，但 optional Skill 必须通过 `--with-optional-skill adk-external-practice-absorption` 显式选择。
- intake 只形成 `review-required` candidate 和独立 owner decision handoff；不再允许直接 clone、注册、复制、安装或发布。

## 调用方迁移

1. 将旧 intake 输入归一到 `external-practice-candidate/v1`，旧 schema 直接拒绝。
2. 由独立 owner 写入 `external-practice-decision/v1`；curator 不得成为批准 owner。
3. `ADOPT|MERGE|ENHANCE` 只授权创建 change，不自动授予网络写、commit、publish 或 source-to-live apply。
4. 运行以下闭包检查：

```bash
bash scripts/devkit.sh validate --strict
bash scripts/check-workflow-closure.sh --profile research-intake --with-optional-skill adk-external-practice-absorption
bash tests/run_all.sh --fail-fast
```

## 升级与回退

- 升级前保留 checksum 已核验的 RC3 artifact；从当前 RC4 source 构建确定性 candidate artifact。
- `release rehearse` 必须证明 `RC3 install -> RC4 upgrade -> rollback RC3` 的 receipt 和 managed hashes 全量恢复。
- 回退是恢复完整 RC3 artifact/commit；不得在 RC4 中恢复旧 Skill、兼容 wrapper 或双 SSOT。
- `~/codex` 与 `~/.codex` 仍需独立 owner 授权和 source-to-live 证据，本迁移文档不扩大写权限。
