# 3.1.0-rc.5 意图与工作项边界硬切迁移

## 适用范围

本迁移面向 `3.1.0-rc.4 -> 3.1.0-rc.5`。RC5 仍是 prerelease，不代表最终 `3.1.0`、Software M5 certification、远端 CI、双 runtime campaign 或 field 认证。

## 破坏性变化

- `manifest.json` 必须包含 `skill_invocation.default_mode` 与 `overrides`；缺失、非法 mode 或未知 Skill override 直接失败。
- task-package v1 已退出 active contract；机器消费任务包必须使用 `adk-task-package-schema-v2`，并补 kind、question、evidence、permission、exit gate、handoff 和 retention。
- decision/research/prototype 固定 `implementation_permission=forbidden`；只有 implementation 可为 `approved`。
- prototype 必须提供 `adk-prototype-evidence-schema-v1` provenance；原型结果不替代 production verification。
- Codex managed Skill metadata 只接受嵌套 `interface`；顶层 `display_name/short_description` 和显式 implicit=true 被拒绝。

## 调用方迁移

1. 为自定义 manifest 增加：

   ```json
   "skill_invocation": {"default_mode": "implicit", "overrides": {}}
   ```

2. 将旧任务包重新生成或人工补齐 v2；不提供 v1 converter 或默认字段回填。
3. explicit-only override 必须有正反路由 fixture；Claude adapter 生成 `disable-model-invocation: true`，无映射 target fail closed。
4. 架构评审默认记录 base/history/hotspots/一阶依赖；全仓扩域必须显式给理由。
5. 运行：

   ```bash
   bash scripts/devkit.sh validate --strict
   bash tests/test_intent_boundary_governance.sh
   bash tests/test_target_contracts.sh
   bash tests/run_all.sh --fail-fast
   ```

## 升级与回退

- 升级前保留 checksum 已核验的 RC4 artifact，并从 RC5 exact commit 构建 candidate artifact。
- `release rehearse` 必须证明 `RC4 install -> RC5 upgrade -> rollback RC4` 的 receipt 与 managed hashes 恢复。
- RC4 target contract 不含 invocation 字段；rehearsal 只能在 release migration 边界从已校验 bundle 安装，并记录 `previous_install_migration=target-contract-hard-cut`，active loader 仍必须拒绝旧 contract。
- Codex source-to-live 在 apply 前必须生成 plan/dry-run 与备份；不得直接编辑 `~/.codex`。
- 回退为恢复完整 RC4 artifact/source-to-live backup；不得恢复 v1 reader、双 schema、legacy metadata 或 warning wrapper。
