# 3.1.0-rc.7 Token、上下文与发布门禁治理迁移

本迁移面向 `3.1.0-rc.6 -> 3.1.0-rc.7`。RC7 封装 task-cost、Token 余量、上下文 receipt、按需路由、双模式工作区门禁和跨仓发布 provenance。

## 行为变化

- 开发期聚合验证必须显式使用 `--working-tree`，并绑定验证前后的 ADK 工作树 fingerprint；该结果不能冒充 release-clean。
- 发布验证使用 `--release-clean`，继续要求 `agent-dev-kit` 工作树 clean，并同步 gitlink、lock 和当前状态证据。
- Task cost 与上下文预算只输出有界摘要；高风险或低置信度结论仍需回读原始证据。
- Codex workflow 默认按需激活，plan v3 对 live target 使用路径级 precondition，并把 already-applied 作为显式 no-op 状态。
- Knowledge Hub reviewing candidate、个人笔记和 active promotion 保持不同权限通道；RC7 不自动提升任何知识条目。

## 升级与回退

1. 升级前验证 RC6 artifact 及 `.sha256`。
2. 从 RC7 exact source commit 两次构建 artifact，要求字节一致。
3. 执行 RC6 到 RC7 原位升级、candidate rollback 和 RC6 artifact 重装。
4. 对比 RC6 安装前后 managed hashes；任一漂移均阻断 release baseline。

## 发布边界

- direct targets 继续为 experimental；RC7 不代表 runtime certification、Software M5 certification 或 final `3.1.0`。
- 本轮只允许 source/evidence commit 与既有分支 push；不创建 tag、不上传 artifact、不创建远端 Release。
- `3.1.0-rc.6` 是唯一回退版本；源码历史回退使用正常 `git revert`，不重写历史。
