# 设计

## 方法

按通用任务、嵌入式领域、optional/外部来源分组读取当前全部 Skill；三个分组覆盖互斥路径。根集成负责需求/设计、共享入口、版本、证据索引和平台交付。实现前固定缺口及可观察验收，修改领域正文或随包参考，复用现有测试入口。

优先让任务执行者拿到正确的真实输入、产物身份和可判定结果。入口只放必需决策，细节进入已随包的直接参考；同一方法保留一个 canonical 实现。跨功能改动均属于“已发布 Skill 的实际执行准确性”这一问题，不借本轮更换路由、许可、授权或资格模型。

## 变更候选

- Review 输入：隔离 Git 已证实 external diff/textconv 可隐藏真实差异并运行 helper，`diff.ignoreSubmodules=all` 可隐藏 gitlink 升级。canonical 原始快照须禁用这些变换；只读 preflight 不刷新用户 index。转换后的视图只作明确标注的补充。
- 运行身份：性能结论区分预期构建产物与实际加载的二进制、库或 dispatch 路径；仅在相关诊断/对比中加载方法，缺实际身份则收窄结论。
- 异步 flaky：已确认为 readiness 竞争时，使用现有事件/条件等待和单调时钟截止预算；不得把精确时序、debounce、取消或超时语义改为只看最终状态。
- 寄存器复位：数据手册明确 undefined/条件性复位不是缺失数字；未核实与已证实未定义分别记录，仅对适用且可安全读取的已定义位比较，不伪造零值。
- 协议边界：在相关传输中明确 stream 分帧、短读/合帧/部分写与 datagram 边界/截断的不同处理。限长、残帧、EOF 和合法空 datagram 按协议分别判断，不新增完整传输框架。
- 其余分组发现：先在 tasks 追加具体观察、边界和 verify，再实施；没有可证缺口的 Skill 保留。

## 验证和回滚

定向测试直接执行发布的代码块或实际消费者，覆盖有意义的反例。沿用原完整回归、profile 容量约束及受保护发布链。新增审查记录准确绑定实际源码和时间；本地源码与连接器发布源码若身份不同，明确保存 tree/逐文件映射，禁止改写历史执行身份。

回滚通过普通受保护 revert 恢复本候选；无需用户数据迁移或运行时重新安装第三方包。
