# Skill 方法沉淀：需求

## 授权与目标

2026-11-18 用户要求“按建议全部优化落地，完成所有批次阶段，全部完成”。本变更完成 ADK 共享规范、三类重点能力验证映射及全量 Skill 的持续维护方法，并沿既有受保护 PR、CI、不可变发行和 Root 消费链交付。

## 边界

- 复用现有 Skill、五项吸收决策、变更合同、评测和发布机制，不另建方法台账、状态机或工作流。
- 不调用付费模型或共享模型额度，不新增调度任务，不安装到真实宿主，不把源码/确定性测试升级为模型效果、Token/费用或产品资格。
- 不放宽预算、失败语义、required CI、独立审查或不可变标签；11.4.2 发布失败证据保留。

## 验收

1. 来源决策统一为既有 `ADOPT/MERGE/ENHANCE/OBSERVE/REJECT`，`adapt/archive-only` 仅为解释性措辞。
2. 七字段方法记录嵌入原工件；明确执行投入与评测证据、开发样例与冻结验收、已测零值与缺测、源码与运行资格。
3. 长任务恢复、需求澄清、代码审查分别映射已有开发任务；全部 65 个 Skill 受既有触发、内容、组合/导出合同覆盖。
4. 现有 PR/main 检查和独立 Spec/Quality 审查通过后发布 11.4.3；Root 只消费具有真实发行证据的 exact source。
5. 未发生的模型试验、独立 holdout、真实宿主和现场验证保留 `not-measured/not-run`，不得用流程完成替代效果证据。
