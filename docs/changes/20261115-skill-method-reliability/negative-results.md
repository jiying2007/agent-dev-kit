# 负结果与已排除路径

- Build 前按 `ctest|tshark|flaky|release|current.state|goal.*resume|错误码|kaslr` 检索 `knowledge/L2-domain/lessons.md`；文件不存在，未据此引用历史经验。当前依据为本轮隔离复现和现存源码。
- 原 CTest 命令对空集、全部禁用、筛选后空集都返回 0；真实 CMake 3.31.6 隔离执行已确认。正常/失败对照用于排除仅由环境造成的误判。
- 原发布命令遗漏 breaking/revert/非标准提交，首发吞掉无 tag 的 Git 错误，非发布 checkpoint tag 改变基线；复现仅使用临时仓。
- 原 state-check 对过长/重复引用列表通过，而同输入的 resume 拒绝；样例均远低于 8 KiB，排除字节预算原因。
- 原 flaky 示例把 PASSED 名称出现次数统计为 failures，方括号名称漏匹配，失败循环经 tee 返回 0；环境输出问题仅使用清空环境后的合成变量验证，没有读取真实凭据。
- 原内核 addr2line 建议缺少重定位分支；host PIE 只用于证明运行时地址不能直接当链接地址，不充当真实内核/设备认证。
- 本机没有 rtk；按已核实的仓库无运行时依赖说明使用原 Bash/Python 入口，不创建伪 wrapper 或声称运行过缺失工具。
- 新增 current-state 边界测试在旧实现上实际失败 7 项；共享约束修复后相关 31 项通过。独立 105 组函数/文件读取差分中，Goal 结果不变，state-check 仅 8 个原误接收输入变为拒绝；这不是 105 个 CLI 或模型任务。
- 真实 TShark 对零字节文件也返回 0，纠正最初“零字节必为读取失败”的推断；最终把零字节、合法零包与目标筛选零匹配标为无目标证据，坏格式仍保留原非零退出。
- 独立预审发现主动采集失败仍可能分析旧 PCAP，以及成功解码不证明 ELF 所属正确；已分离纯离线/主动模式，主动命令用失败依赖并使用本轮新路径，地址解码先核所属内核/模块/段。三条采集失败注入只验证 shell 控制流，不充当 live capture。
