## 关键实现和方法判断

**共享 current-state 校验保持原消费者边界。** 字段约束统一为 evidence/blockers 最多 8 项、history 最多 3 项、next_actions 1–3 项，字符串非空白且唯一。两入口保留原 reason 词汇；state-check 的 schema 短路和原错误聚合行为没有被统一成另一套诊断。非字符串及不可散列成员先被类型检查拒绝；严格 JSON、有界读取、路径拒绝、只读恢复与无执行权限边界未改变。

独立的 105 组旧/新函数及真实临时文件读取差分中，Goal 检查完全一致，state-check 只有 8 个原误接收输入变为拒绝，均属于重复或过长列表。本证据不是 105 个 CLI 测试。公开入口新增边界、错误码及原有读写/拒绝回归由实施日志与最终全套相互覆盖。

**发布清单不再丢失提交或默默改范围。** 示例要求先由项目政策和实际发布记录核实正式基线身份，再解析 commit、检查祖先关系与完整历史。首发显式选择；不存在、非祖先、shallow、Git 或参数错误不会回退成空成功。完整 hash、subject 和 body 保留，breaking、revert 和未知类型交人工核实际影响。tag 可解析和空范围均不自动授予发布结论。

**flaky 方法保留每次观察，不用日志命中计失败率。** 方法要求从框架报告按精确 ID 读取 outcome，区分 failed/error/skipped/missing 和实际分母。示例以参数数组执行有界轮数，逐轮新目录、完整原退出码与独立日志；参数或采集失败退出 2，任一命令失败则总体退出 1。它不自动验证所有框架报告的完整性，不把进程退出 0 当作用例稳定性。单次命令的超时/取消仍由已核项目入口提供。环境示例只输出变量名，合成凭据值未进入结果。

**CTest 与抓包将空证据显式保留。** 两个 CTest 示例的空集、全禁用和筛选为空均被真实工具拒绝，正常/失败仍保留其行为；运行时 skip 即使退出 0 也没有计为已执行断言。离线 TShark 使用 `-n` 与实际显示过滤器，保留帧号、时间和数量；坏格式失败，零字节、合法零包和零筛选匹配标为无目标证据。主动采集仍有范围、权限、时间和包数限制。

**Artifact 与错误码扫描对齐实际能力。** Artifact 的 status 与 workflow stage 分开，不再承诺不存在的逐 artifact 状态迁移校验。已有 workflow 的 verified 前置条件、PASS/PASS 与 verdict 约束在隔离消费者夹具中得到正反例验证；模板 owner/findings 等字段已补齐。夹具构造的 verified 状态只验证消费者语义，不是本候选真实验证或发布资格。错误码扫描去掉文件名前缀后能发现跨文件相同负十进制字面值；宏、表达式、其他进制、别名和命名空间仍需另核。
