# Skill 实际任务方法可靠性

## 目标与范围

用户要求全面优化全部 Skills 的功能、性能和易用性，并已授权公开推送、受保护合并和继续深入优化。本轮在 11.3.2 候选基础上，对 56 core + 9 optional 的正文、适用 references 及实际消费者再次深审，优先修复能由具体任务反例确认的错误；保留有用且没有确认缺陷的方法。

统一问题是：Skill 给出的命令或状态解释可能把空结果、遗漏、不同接口的矛盾判断或错误证据当成成功。本轮只修既有工作流和共享实现，不新建 Skill、门禁、执行平台、模型评测或运行时。

## 验收

1. 同一 current-state 的字段边界在公开 `goal state-check` 与 `goal resume` 一致：history ≤3，evidence/blockers ≤8，next_actions 为 1–3；字符串列表唯一且非空白。保留各入口现有错误码及短路/聚合行为（例如 `current-state-next-actions-limit` 与 `state-next_actions-invalid`），不要求两入口的 reason 字符串相同；严格 JSON、有界读取、路径拒绝及只读恢复边界不变。
2. 发布变更清单基于明确核实的正式发布基线；首发有明确路径，非发布 tag 不改变基线。正式发布身份须有项目政策/已核证据，不能仅凭 tag 可解析。完整保留提交身份、subject、body、breaking/revert/未知类型；不存在、非 HEAD 祖先的基线、shallow 不完整历史和 Git 失败不得变为空成功。
3. 偶发测试方法使用测试框架实际结果和执行次数作分母；名称包含空格或正则字符不能误分类。重复执行有界、日志独立、保存每次真实退出码；采集失败不得刷绿。环境比对不输出任意匹配变量的值。
4. CMake 与 SIL/HIL 的 CTest 示例将空测试集、全部禁用及筛选后为空作为失败；正常与真实失败结果保留。编译成功仍不能证明目标上执行成功。
5. 离线抓包命令产生可归属的实际包结果，避免默认名称解析和无意义空输出；空文件、坏文件、零包或目标 display filter 匹配零包不冒充协议验证成功。
6. 内核/模块回溯先匹配制品与地址所属，区分 function+offset、运行时 PC 和链接地址；缺 KASLR/模块映射信息保持 partial，不通过关闭防护或猜偏移生成结论。
7. Artifact 主文、reference 和已有 workflow 对状态语义一致；模板满足声明的 owner 等字段，签收和状态文本不代替真实验证。
8. 跨文件重复错误码的字面值候选扫描能发现相同值，并明确不能证明宏/表达式/别名/不同命名空间的最终冲突。
9. 全部 65 项都有实际审查决定；原身份、安装选择、路由和权限不变，8 个已有 profile ratchet 不提高阈值；收益只报告实际测得范围。

## 非目标

不新增 Skills、绕过受保护检查、安装到用户运行时、操作真实设备/邮箱、付费模型 A/B、计划任务或低风险路由授权。真实模型成功率、Token、成本和端到端时延仍未测量。
