# 任务重试的重复过程观测

## 目标

真实执行在重试、恢复或子任务中可以再次加载同一 Skill，并重新执行同名过程检查。已有事件导入按 Skill 或 guardrail 名称全局拒绝重复，导致事件身份不同的合法重试观测无法进入任务证据链。本变更允许此类重复事件，保持完整原始账本和既有计量、验收、配对语义。

## 边界

- 只修改任务观测导入的重复暴露归一化、对应回归和必要说明；不运行模型、不新增 runtime、调度器或统计引擎。
- 同名 Skill 的内容摘要或 primary 角色不一致仍拒绝；不同 primary Skill 仍拒绝。重复 event_id、call_id 或错误 seq 仍拒绝。
- 不删除原始事件，不把重复加载算成多份 Skill 身份，不去除重试模型调用、工具调用、人工干预或失败。
- 同名过程检查可重复，任何一次 failed 都必须保留为整次运行的失败；后续 passed 不得覆盖。每个过程证据引用仍须读取、核对和纳入输出别名保护。
- 报告继续保持 caller-observed/test-only；不补造真实宿主数据，不提升发布或产品资格。

## 验收

1. 两次加载同名、同摘要、同 primary 角色的合法观测可导入，原始事件引用绑定包含两次加载的完整账本。
2. 两个 attempt 的模型/工具成本均保留；最终成功仍不是 first-pass success。
3. 同名 Skill 摘要变化、primary 冲突、重复事件身份、多 primary Skill 和 no-skill 对照污染继续拒绝。
4. 同名过程检查的 pass→pass 可导入；failed→passed、passed→failed 均保持过程失败，非适用与通过组合保留可适用检查。摘要验证和证据读取不可因重复而省略。
5. 合法重复暴露能通过现有任务配对前置核查，报告与既有统计权威保持不变。
6. 完成确定性 RED/GREEN、受影响回归、适用完整 CI、独立 Spec/Quality 审查、受保护发布，再由消费者既有事务一次晋级。
