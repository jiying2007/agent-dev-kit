# 设计

## 方法与边界

- F1 在 adk-fault-injection-recovery 原入口中改写重复恢复/SLA语句，以精炼的对照、命中证据及判读要求替代重复内容；该 Skill 总字节不超过基线 3559 bytes，不移动内容到其他 Skill，不提高原 Profile 限额。未命中使用既有 not_evaluated，不增加产品状态。
- F2 在 adk-email-imap-fetch 原 Workflow 中增加仅对精确时间请求适用的分支；普通日级搜索流程保留。时间基准由用户目标决定，接收时间不用 Date 替代。候选边界须有覆盖依据，预算不足不擅自全邮箱扩扫；不发布固定日期扩展算法或通用 IMAP 客户端。
- Skill 资产总数、默认 Profile 和真实授权链不变。两个 Skill 各自更新版本/日期，ADK 按现有发布机制前移至 11.3.12；版本/目录派生内容由真实现有入口处理。

## 验证设计

固定正常控制及故障/时间边界字面量。原探针、夹具和原输出保持不变；新增回归可以重用其受控输入，但不把本地模拟协议当成服务器一致性认证。既有聚合入口注册定向模块；不创建新 Gate。补实际导出完整性检查。一次最小上下文消费者观察用于检验方法是否可执行，单次观察不构成 A/B 或泛化效果结论。

独立设计核验通过后明确三项实施口径：F1 缺少命中计数或等价证据时仍为 not_evaluated，不由错误返回或健康 follow-up 反推已命中，不伪造时延；F2 新回归隔离时间条件，不沿用同时经过完整地址筛选的旧期望；非法/缺失/无已知时区的所选时间字段及数量/字节预算耗尽必须实际触发 partial，保留成功项与未判定范围，不能隐式使用主机时区。普通日级控制实际执行日级路径。

设计/整合由 parent，F1 实施由 diagnostic_methods，F2 实施由 task_data_methods；embedded_methods 作为只读独立审查，不修改实现。相互文件写范围分开。实现证据、消费者输入输出及最终 reviewer 报告分别绑定源码身份；只有精确冻结源码运行的检查才标记为该提交执行。

## 来源与已有结论

Linux 6.12 fault-injection 文档的 fail-nth 明确区分已注入与尚未注入；RFC 9051 §2.3.3/§6.4.4 与 RFC 3501 对内部时间、日期筛选语义的说明为 F2 依据。原文按需读取，不复制上游实现或泛化到未测环境。

本轮六个嵌入式实现 Skill 为 KEEP；诊断 harness 关联仍为 OBSERVE（未找到真实响应解析 consumer），不制造新 invocation 接口。

## 风险与回退

主要风险为精炼时漏掉旧安全条件、把工具成功误写为目标命中、候选日期范围漏取、时间缺失被当作未命中。以旧合同测试、正常/反例、源码差异、独立审查控制。回退使用本 PR 的受保护 revert 或消费前一不可变版本，不清理旧日志、不改变历史资格。
