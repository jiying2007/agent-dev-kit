# 需求：故障命中与邮件时间筛选的实际判定

用户要求继续优化其他 Skill 并落地。本变更基于 ADK 11.3.11 / fad9d4d170a97c5dbb2c5261432fa2120bfcc3c9；沿用本会话已有提交、受保护 PR 合并、独立 AI 审查及 source-only 消费授权。

## 目标与范围

仅增强两个现有 Skill：故障注入须证明实际触发；IMAP 精确时间请求须区分日级候选搜索与最终时间判定。两者是有真实受控对照支持的方法增强，不是已证实的 ADK 运行态判定器漏洞。

## 验收

- F1：保留相同输入的无故障对照；区分配置、实际命中、检测及恢复。未命中或命中不可观测沿用 not_evaluated，不填零时延或宣称恢复成功。确认命中后仍验证功能、数据和资源恢复，原设备授权/预算/停止/回滚要求不变。
- F2：精确时间请求复用已明确的时间基准、时区和区间；区分 INTERNALDATE 与 Date，日级 SEARCH 仅形成可证明覆盖范围的候选，再只读精筛。不能无条件套用前后一天；候选超预算、所选时间缺失或不可解析时保留成功项和未判定范围，沿用 partial，不能偷换时间字段。
- F3：保留普通日级请求、UIDVALIDITY/UID、EXAMINE/BODY.PEEK、数量/字节预算与不修改邮箱状态的既有要求。完整地址精确匹配仅作为本次未采用的边界研究，不扩展生产范围。
- V1：实际 host 正常/未命中/已命中/坏清理对照，以及真实 imaplib 与本地 stdio 协议夹具的日级正常、跨时区、字段不同、缺失/非法字段、边界及预算控制；原始命令、输入、输出和限制可追溯。
- V2：现有聚合测试注册、strict/source budgets、实际目标导出、完整回归、独立 Spec/Quality 及受保护 PR/main CI 通过后发布新 patch，并完成 Root source-only 接入。

## 非目标

不修改上一轮五个 Skill、路由、Profile、预算阈值、运行态接口或产品资格；不引入新 Skill/运行时依赖。无设备写入、真实邮箱/认证、外部消息或新付费模型任务；不声称 Token、成本、真实恢复 SLA 或原生消费效果已测得提升。
