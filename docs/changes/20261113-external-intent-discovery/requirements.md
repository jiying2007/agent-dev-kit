# External Skills / Prompt discovery — requirements

- Lightweight requests to compare quality external Skills or trace external Prompt callsites should resolve to existing primary research Skills, not need an all-purpose adoption workflow.
- The heavier `external_practice_absorption` intent keeps its exact machine routing, curator/owner separation, review-required candidate and no auto installation.
- Do not broaden tool authority, change Manifest routing, install external code, or load every Skill. Preserve `non_triggers` and explicit negation behavior.
- Prove direct trigger positives/negatives and whole-catalog primary/abstain behavior using the production `match_text` contract.
- Model task success, real host selection, runtime tokens/cost and latency: `not-measured`.

- Explicit broad public searches require `source-discovery`: bounded tool-authorized discovery, immutable provenance, reviewed/unreviewed coverage and no fictitious results. A given single repo should remain the cheap `method-only` path.
