# 设计

## 任务路径

直接修复现有技能的工作步骤、命令和交付判断；README 与已有 usage 文档增加任务入口，保留维护命令参考。全量核查按需求设计、计划执行、嵌入式实现、诊断性能、测试评审、发布交接、知识与资料获取分工。使用已有目标和输入，不新增平行台账或运行时机制。

实际使用入口核验发现 catalog 只检索名称/描述，用户采用 Skill 已声明的触发表达也可能找不到它。复用读取过的 frontmatter，把正向 triggers 纳入现有 catalog find 的检索内容；保持大小写不敏感、子串匹配、type 范围、TSV 输出与只读行为，不将命中解释成已安装、路由适配或执行权限。测试逐一使用全部 65 个 Skill 的已公开触发表达找回所属条目，并验证 optional/core 范围不串用。

## Goal 恢复

`goal plan-check` 保持只接受可执行批次。仅 `goal resume` 使用显式只读恢复校验：允许原批次条目已关闭或被阻塞，但仍要求已关闭条目有证据引用、依赖/验收映射一致、输入有界且不含符号链接。不支持借恢复自动选择、执行或完成下一批次。保留原批次编号，显示条目状态及未关闭依赖，避免为展示进展重建 Goal。

恢复摘要输出 goal_ref、milestone、blockers、evidence_refs、work_in_progress、next_actions 和 history_refs；这些是输入中记录的事实，内容未验真，不授予重试或完成权限。goal_ref 既有语义允许原需求引用，本轮不强加路径相等。8 KiB 输出限制和原输入限制保持不变，超限明确失败而非静默截断阻塞信息。示例预算改为诚实未知，不让固定 300K 示例成为实际默认值。

## Skill 修复

组件兼容分别判断源 API、二进制 ABI 与行为；真实目标/产物/旧消费者决定工具和测试，符号表不能替代布局证据。简化示例必须保持后续副作用，测试命令从项目实际入口选择。测试策略负责设计并把已授权实施交给实现职责，不隐式提升只读权限。领域工具按实际目标分流，最小有用结论优先，失败保留原退出码。

Pilot 主入口存在空 Goal、泛化先决条件以及已不存在的来源项目脚本。改为真实任务 smoke/compare 分流、产物验收与环境状态分别报告；仅当目标项目声明时使用原健康检查组合，避免对普通消费者强制内部脚本。单次结果不提升产品资格或触发未授权安装/费用。

## 保留的能力缺口

全部职责的源审查不代表每项运行效果都已优化完成。E1 的 derivation 存在，但当前 Manifest 没有可信 low-risk implementation 路由可到达它。修正文档中 micro/零命中可直接执行的矛盾，明确成本回执不授予权限；本轮不凭用户关键词推断低风险、不新增第二路由权威。真正 E1 准入需要单独的可信风险输入、影响边界和拒绝路径设计，仍未实现。此范围决定保留原授权与路由行为，不能列作已经获得的效率收益。

## 验证与回退

公共 Goal 调用点先全库检索；新增行为以 CLI 和状态输入的可观察结果测试，不添加逐字匹配新文案的测试。Skill 文本沿用既有结构/内容/路由/预算检查，并独立核对关键示例。独立审查绑定实际 diff 和验证结果。回退本 PR 恢复 11.3.1 行为；无安装、模型或设备状态变更。
