# 设计与执行边界

官方 CLI 和本地模型负责实际执行；ADK 只提供冻结 Skill 资产、任务合同和验收入口。下载固定发布资产后核对完整 SHA256，再解包到任务专用目录。模型下载属于准备阶段，取得实际 digest 后先写冻结清单，再启动两个条件；不得执行中途替换模型。

使用同一初始任务仓库快照复制两个工作目录，Skill 及宿主配置放在 grader 的 work/ 集合之外。宿主仅收到原始任务文本和用户式 Skill 请求，不收到验收期望、预期答案或修复诊断。最终验收由独立调用方执行现有 grade-task。

优先使用官方 standalone CLI 与持久 session export/log；先核对稳定版本实际接口，不能用当前开发文档猜测不匹配字段。若需要运行本地 server 获取durable log，只使用官方服务，记录精确session身份，不引入第二个推理循环。关闭辅助/远程能力；原始事件不完整时只报告可证明事实，不制造完整coverage。

本地CPU资源不足、安装失败、模型无法调用工具或时限内没有完成，均是有效先导结果或环境阻塞。最多一次有证据支持的环境准备修正；任务本身不重试以筛选成功。所有失败与配置变化保留。

计划与验收由 ai/root 负责；环境/执行委派给独立执行者，原生任务由固定的 OpenCode 模型完成。只读审查检查来源和结论边界。不会把本工作区代理的编码/审查当成本次模型A/B。
