## 目标与基线

用户要求继续全面优化所有 Skill、检索优质外部方法并完成 ADK 落地；此前明确允许推送合并，该授权本轮仍适用。起点为主线 `e13bd4788d5638c1eb34c169870f19dfd5285b6b`、tree `9c0ea54bc3205c2a3b6c772ec22a40b6d096109f`，source/component version 11.3.6。

对全部 65 个注册 Skill 重新逐项检查触发边界、输入/输出、真实执行、消费端可用性和上下文负担；已有正确方法保留，已证实缺口修复，不用无差别改写或新增 Skill 数量充当完成。

## 验收

1. **全覆盖**：65 个入口及实际读取的直接资源有路径、基线摘要、逐项判断和理由；最终清单闭合到改动、保留或明确限制，不能漏项或以抽样冒充全量。
2. **外部吸收**：广泛搜索后读取原作者具体文件，保留 commit/blob/许可证或缺失状态；逐方法比较现有 ADK，记录采用、已覆盖或拒绝理由。外部声称的效果不当作本项目测量。
3. **独立导出与只读 Review**：并行工作包在纯 Skill 导出中可按随包正文创建；不存在的源仓模板不得成为强制前置条件。保留范围、权限、owner、停止条件、验证、报告和证据边界。Review 的反馈 reference 复用已验证的单一快照命令，不残留会刷新 index 的重复路径；真实 Git 内容/mtime、混合 staged/unstaged 和已提交分支验证保留。
4. **结果与范围一致**：数据获取父入口保留子 Skill 的完整、局部、失败、未验证状态及已取得内容/未取得原因；成长复盘的 metadata 与正文都采用已授权范围和 index-first；归档摘要不一致先保留旧证据、核明变化来源，不能只更新 hash 抹平未知异常。
5. **真实测试资格**：CMake 示例的零测试、全禁用、全部跳过和实际通过区分清楚；筛选/配置及报告绑定同次执行，编译成功或 CTest exit 0 不自动代表有效测试通过。先实证当前缺口，再确定最小修正。
6. **超时可诊断**：命令示例总执行上限仍为 15 秒，无隐式重试；超时失败保留 stdout/stderr 和执行身份。若实证存在子进程残留，终止本次拥有的进程组并保留输出，不能影响其他进程。成功和普通非零退出语义保持。11.3.6 的一次 CMake 超时根因仍未明，诊断增强不等同根因修复。
7. **验证与交付**：定向真实反例/回归先行；最终共享检查、8 个原 profile 字节上限和完整回归不放宽。版本计划 11.3.7；独立只读审查、精确源码 PR CI、正常合并、main CI 和自动 Release 均以实际结果验收。
