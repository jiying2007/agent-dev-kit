# 评估链路审查修复批次

## 目标与边界

修复真实运行时评估的结构化输出误判、敏感错误回显、逐例模型错配，以及源测试层合成评估的混合意图和 JSON 输入校验问题。保留现有 dirty 工作区；仅本地源码与测试，不执行真实模型调用、提交、推送或运行资产应用。

## 风险与验收

- 任何缺失、类型错误或额外字段的运行时结果均不得通过；报告不得包含 CLI stderr、stdout 或模型原文。
- baseline/candidate 每个任务的实际模型列表必须一致，且模型未观测时不得产生可比性通过结论。
- 合成评估中的混合高风险意图必须 fail-closed；合同、标签与输入 JSON 拒绝重复字段和非有限阈值。
- Python 3.8 定向回归通过；共享评估逻辑再运行严格验证。真实 runtime 和 source-to-live 另设验收线。

## 执行检查点

1. 修复运行时输出与报告：定向测试和隐私反例。
2. 修复比较与合成评估：逐例反例和数据契约回归。
3. 汇总验证与开放问题：不把源码测试通过推断为生产运行验证。

重试预算：同一失败最多两次无新增信息后重新审查假设。停止条件：共享契约冲突或无法保持 Python 3.8 兼容时重新规划。
