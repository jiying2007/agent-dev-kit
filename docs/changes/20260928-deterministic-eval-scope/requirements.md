# 确定性路由评测的检查范围

## 目标

修正 `eval run --suite deterministic` 的结果语义：任务包含 `expected_safe`，但该套件只执行路由匹配。`status=pass` 不得被解读为安全判断通过。

## 验收

1. 总结与逐用例结果均明确披露安全判断未执行；路由准确率等于现有路由成功率，安全准确率为空值，不填 0 或 1。
2. 既有路由评分、退出码和真实 runtime 评测合同保持一致。
3. 用反转 `expected_safe` 标签的确定性用例证明路由结果不依赖安全标签。
4. 文档说明确定性路由、静态 effect 与真实 runtime 的独立证据范围。
5. 报告绑定 manifest 摘要与已解析、按原顺序选中评分的任务集摘要；显式说明它们不构成原子源码快照或原始文件字节身份。
6. 评分前冻结任务序列，后续调用期间原可变对象的变化不得使结果与摘要分离。

本批只保留本地未提交改动；不触发真实模型、外部写入或 source-to-live 应用。
