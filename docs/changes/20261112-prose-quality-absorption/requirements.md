# 成稿表达质量方法吸收 — Requirements (2026-11-12)

## Scope

- 针对已有自然语言成稿，提供可选、独立的语言审阅与最小改写能力；以中文为主，也支持按用户指定语言处理英文，不建语言平行 Skill。
- 只吸收可通用的工程方法：具体问题定位、修改前后保真核对、拒绝机械规则与过度编辑。
- 用户只请求诊断时不改正文；明确请求润色时避免强制额外确认轮次。

## Acceptance

- 新 Skill 仅登记在 optional_skills；core / embedded 默认配置不增加 Skill 负担。
- 元数据具备正触发、非触发、输入输出和权限约束；核心技术文档例子覆盖数字、术语、否定对比、限定词、表格/代码边界。
- 既有 manifest/contract/catalog 保持单一身份来源，生成目录与 manifest 一致。
- 既有确定性触发矩阵、可选 Skill 安装和内容测试可运行；不把源码级验证当作真实模型质量或 Token 费用改善证据。
- 外部项目许可边界清楚：不复制 CC BY-NC 4.0 的代码、语料、脚本或受保护规则表述。

## Non-goals

不创建“AI 作者检测器”、新 Agent/Workflow、词汇黑名单、统计阈值准入、自动定时任务或第三方模型调用；不改变 ADR、技术事实验证及仓库发布权限。
