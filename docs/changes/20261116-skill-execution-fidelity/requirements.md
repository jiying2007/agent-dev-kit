# Skills 执行保真与可用性

## 目标

承接用户“继续全面深度优化所有 skill，全网搜索优质 Skills，深入优化 ADK”的既有授权。基线为 `907080d5a0f6e49daa93e217f60383b23ed89d37` / `11.3.4`。逐项复查 65 个现有 Skill 的入口与直接引用，用实际失败选择修改范围，保留已有效的方法。

## 验收

1. 辅助 Skill 的同组提升必须遵守目标主 Skill 的排除条件及已明确拒绝的意图；正常同组提升仍可用，不能推导额外权限。
2. BSP 示例依据已确认的目标架构、工具链、配置及 CPU/RAM 预算构建；接口版本示例明确适用的兼容策略和最低所需能力，不能无条件降级。
3. 设计拷问保留稳定问题身份；只回答部分问题不等于确认剩余问题，修订上游决策应使依赖决定重新待确认；已有明确执行任务不重开访谈。
4. 任务评测拒绝注册/观察窗口以外开始的试验及同 task 验收项组成漂移；结果状态与证据允许随试验变化，不能将组成一致冒充 grader 实现语义一致。单次 compare 复用已验证合同，跨调用重新加载；用同机同输入实测本地耗时，不推断 Token/费用收益。
5. 只通过既有 Manifest、路由、导出和验证链交付。原预算/安全/发布门禁不放宽，完整回归、独立 Spec/Quality、受保护 PR、主线 CI 和正式 Release 分别核验。
6. 分支收尾可复用可信可回读、同目标/动作/范围且未撤销的既有明确授权；计划、沉默、PR 正文或模型摘要不能新授权限，删除等未覆盖动作独立判定。
7. 分发 Skill 不隐式依赖 `rtk`；展示原工具命令，宿主若明确要求包装器仍服从宿主规则。ADK/llm_agent 内部管理命令只在已核验的相应源码根执行，不能假定消费端带 ADK 源码/Python。

## 非目标

不新增 Skill、运行时、定时巡检或付费模型调用；不涉及 KWS/audio/safe、用户设备刷写或生产部署。不把第三方代码/安装器整包引入。65 项覆盖审查不意味着每项都要修改，也不等于模型效果认证。

## 执行约束

已有推送、合并、发布与独立自动审核授权持续适用；不绕过仓库保护。用户禁止消耗 Codex/ChatGPT Work 共享额度，所有实验限当前会话的只读研究、源码工具和既有 GitHub Actions。`rtk` 在本执行环境中实际不可用，直接运行现有命令并保存原始输出，不伪造包装器。
