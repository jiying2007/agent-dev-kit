# 实现与试点设计

复用 `adk-code-review-loop` 的完整审查入口、详细参考、覆盖账本和审查模板。首轮结束、覆盖状态、提交判断是报告事实。现有提交门禁和正式 owner 委派验证器维持各自职责。回退时同时撤回 Skill、参考及定向回归改动。

## 阶段 A 工作包

| 项目 | 入选或完成证据 |
|---|---|
| F20 OTA 高风险样本 | 首轮候选身份和隔离副本、当时可见材料、原生 s6 与测试替身、可独立重放的已知重大场景 |
| GROS Sensor 投影头高风险样本 | 首轮候选身份和隔离副本、对应的编译数据库和投影目录、真实 clang-tidy 运行证据 |
| 低风险对照 | 范围明晰的冻结候选、独立评估者确认范围内无已知重大问题 |

准备回放时预先锁定评分参考、样本替换、预算和责任人。每个高风险样本至少含一个已独立确认且可复现的重大或阻断问题，优先选择包含多等级问题的样本。两组分别使用独立上下文和共同允许的材料，固定工具、模型配置和预算。A 组沿用现行方式，B 组预列场景，逐项检查或记录缺口，再一次性交付。独立评估者盲评。按冻结参考集统计各等级类别与场景命中，另报误报、错分级、错放行、有效新增与成本。任务超时保留已获结果，受污染或基础设施失败按预登记规则留痕。低风险两组沿用现行方式，单报其成本和误触发。

进入真实试点需两个合格高风险配对、一个低风险对照、可核验的隔离及协议执行、可回溯的评分，以及独立评估和阶段决定。真实试点事前确定各拟评价等级的样本下限和阈值，用同口径盲审首轮原候选。后验发现单报，保留冻结分母。重大漏检、错放行和成本分别裁决。任一阶段出现确证的模拟或真实准入错放行、关键证据缺口被误标通过时，立即暂停新分配、受影响的放行结论和升级。保留证据，现行门禁重判在途候选，通知项目负责人跟进已放行候选。修正经独立复核后，由试点负责人裁决恢复。报告模式及硬门禁由后续阶段证据决定。
