# 输出写入边界修复

## 目标与授权

用户于 2026-10-23 明确要求“全面吸收，全面优化，落地闭环”；承接已完成的两仓审查，关闭 ADK-06、ADK-04、ADK-05。实施、独立自动审核、提交、受保护合入与组件发布均在既有授权范围内。基线为 bf9ec8164e2c80394ce997f8a8b51515cad4746e。

## 验收

1. export 的同根或根外 target 符号链接不得授权清理；拒绝时所有无关文件保留。
2. 解析路径前、取得 writer lock 后和实际替换前保留并复核请求路径身份；正常导出、替换、恢复继续有效。
3. Native 所有输出必须在 stage 或任何输出写入前完成集合预检：普通文件类型、路径/硬链接别名、输入输出别名、祖先链接。
4. 目录、FIFO、同路径输出必须提前拒绝；已知非法第二输出不得改变第一输出，不得执行 discovery/load/trigger。
5. 多输出全部序列化和 staging 后发布；后项发布失败应补偿恢复已替换输出，恢复失败须保留可恢复材料并报告真实状态。
6. 使用无害本地 fixture 验证，不生成真实 runtime、签名或产品资格。

## 非目标

不改变 runtime 认证语义、不新增 Skill/Gate 框架，不写 live 用户目录，不把多文件 rename 宣称为天然原子事务。
