# 执行时序与诊断精度：需求

## 目标与授权
用户在 2026-11-16 授权完成既定 Root source-only 接入，并要求继续全面优化所有 Skills、检索成熟外部方法、推进 ADK 落地。ADK 基线为 v11.3.8 / `913b6b3a0838ccddae252a3a8536ac7d41598810`。本轮重新审读 56 core + 9 optional，只有存在可说明的执行缺口才修改。

## 验收
1. RTOS 周期任务区分毫秒和 tick、相对延迟和绝对周期，检查量化/零周期/范围；超期策略有界，软件 timer callback 不阻塞共享服务。
2. 调试二分先验证信号：不可测修订不标 bad，测试基础设施故障停止；跳过造成的不确定区间不伪称唯一根因。重跑可能清空故障产物时先保留原始证据。
3. 事故时间线区分发生与采集时间、时区及来源时钟的不确定性，不从采集顺序推断因果。
4. 空白 Skill 生命周期模板的检查结论保持待验证，不能预填成功。
5. 保留各 Skill 已通过的方法和权限边界；原有 profile 容量门槛不变；采用官方 API 或固定上游源码，拒绝无法核实的社区示例。
6. 有实际定向执行、独立审查、完整回归和正常受保护发布；源码校验、人工构造案例、Agent 消费案例、运行态/产品资格分别报告。

## 非目标
不安装外部 Skill 包、不执行外部安装脚本，不启动付费模型、Codex/ChatGPT Work CLI/Cloud 或新巡检；不改真实设备、宿主运行资产或产品资格。当前没有模型 A/B、板端时序或成本测量，不作相应效果声明。
