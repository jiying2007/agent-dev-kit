# 执行时序与诊断精度：设计

## 边界
沿用现有 Skills 和测试入口，不新增 Skill、运行时依赖或审批门禁。设计阶段由主 Agent 冻结验收，三组只读审查提供上游来源、实际探针和最小改动建议；实现任务再单独分派，最终由未实现候选的审查者只读复核。

## 修改位置
- `adk-rtos-task-design`：将周期唤醒与共享 timer 服务约束放入现有任务模型/运行验证路径；区分到点未阻塞和真正超期，stop/delete 入队成功不证明回调已停止，不提前释放回调上下文。精简重复概述，保留原响应时间公式及适用条件。
- `adk-systematic-debugging`：在现有二分与按需反馈循环补充有效信号、skip/abort 和重跑前证据保全。只有 Git 二分场景使用 Git 退出码，不能套到一般模块/输入二分。
- optional `adk-incident-rca-report`：强化现有时间线一步和报告字段，保持短报告默认，不增加强制大模板。
- optional `adk-skill-composition-governance`：空白 Creation Gate 改为待验证；真实证据支持后才填写 pass，保持已运行/未运行语义。

## 验证设计
隔离 Git 历史验证真实回归、不可测修订、基础设施中止和歧义结果；隔离临时产物验证重跑前留存。RTOS 探针明确绑定实际 API/宏并区分算术/调度模型与目标板测量。事故案例固定异时区、迟到采集和未知时钟偏差。模板检查解析表格并验证空证据不预填成功。

新增断言围绕禁止结果和可复现行为；不以只搜索新增口号的测试证明 Skill 有效。必要的静态契约与真实执行证据分开记录。保留已有成功路径及全部原 profile 阈值。

## 交付与回滚
修改的 Skills 提升 patch 版本，ADK 同步下一个 patch 版本；完整回归冻结后不再修改被测源文件。独立审查绑定准确 source/tree/patch。正常 PR、main CI、正式不可变 Release 和发布后归档核对完成后更新消费源指针；回滚通过独立 PR 恢复对应版本与生成投影，不覆盖历史资格证据。
