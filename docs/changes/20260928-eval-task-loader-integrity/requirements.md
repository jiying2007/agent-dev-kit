# 评测任务数据完整性

## 目标

让 JSONL 评测任务先经过整份文件校验，再按 `--limit` 返回前 N 条评分任务。任务身份、输入预算和结果摘要应保持一致，避免一个有效前缀掩盖后续坏数据。

## 验收

1. 重复任务 ID、重复 JSON 字段、非对象记录、错误字段类型、非 UTF-8、符号链接及超预算输入均 fail closed。
2. `limit` 必须为 1–10000 的整数；即使只选前 N 条，也检查整份文件。
3. 单次读取有 1 MiB 字节预算、10000 条任务预算；现有 Software M5 任务集与评分行为保持可用。
4. 报告摘要只绑定已解析且实际选中评分的任务序列，不冒称整个原始 JSONL 文件身份。
5. 直接调用确定性评分函数时，空任务集与重复任务 ID 也必须拒绝。

本批只在本地工作树实施，不执行真实模型或外部写入。
