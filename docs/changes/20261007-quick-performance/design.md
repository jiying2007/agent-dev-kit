# 设计

只读剖析显示validate_repository加载两份同源Manifest，_json_schema_failures调用三次；profile含计量开销，只作热点归因，不用作收益证明。首个65532直接挂载剖析因host文件权限失败，后续按源文件非root属主只读剖析成功，不改变门禁镜像或实际baseline。
第一批优化：validate_repository复用同次读取的Manifest，公共validate_assets入口保留；frontmatter统一安全加载，优先PyYAML CSafeLoader，可用性缺失时保持原SafeLoader。两者都拒绝Python对象构造器；不改变解析输入、调用点和有效值语义。不承诺一般YAML资源防护。
第一批实测138084ms仍超限，不能宣称达标。第二批实现Manifest实例内单项成功缓存：每次重读schema bundle，canonical data/schema bytes与validator身份都相同才复用成功；JSON roundtrip不保留结构的值不缓存（如tuple或非字符串键），错误不缓存。nested mutation/schema file drift/非JSON类型/资产文件变化必须补负例；不缓存完整asset校验，不采用跨进程持久化。
CLI按所选命令延迟导入域模块，help不导入model/jsonschema/YAML；原main、ROOT、handler和delivery/eval/catalog委托保持。AST边界检查改为遍历所有节点，既支持局部导入，也更严格发现隐藏的直接delivery域导入，不删除委托要求。
PyYAML官方文档说明C和Python实现可能有细微差异，因此兼容声明只覆盖受测资产与标量/alias/date语义，不泛化为任意YAML完全等价：https://pyyaml.org/wiki/PyYAMLDocumentation。
共享model/validation/YAML调用点串行修改和验证；完整回归冻结后不继续追加内容。
第三批仍121118ms，按相同schema在不同fixture路径导致重复meta校验的证据调整编译缓存key为raw bytes，保留8项上限、变化失效与原source-specific JSON错误。validator从未使用物理文件名作reference base；不删除meta验证，首次相同bytes仍完整校验，失败不缓存。新增两Root相同schema只编译一次测试。
第四批120234ms仍失败。projection负例改为直接执行相同sys.executable下的公共模块CLI，每个probe仍冷进程、外部cwd、fixture-source PYTHONPATH及ADK_ROOT绑定，strict/quick/strict+quick断言不删；避免每次重复shell解释器选择。实际shell validate仍在test_validate起始验证；完整launcher测试继续覆盖版本选择、缺失/unsupported及帮助契约。
第五批121219ms显示贴线波动不能认定达标。显式版本身份前置条件：strict且非quick身份失败时，保留asset/eval/identity失败结果并标governance_checks blocked/checked0，不运行下游治理；整体fail。身份有效时五项治理均执行，强制失败仍可被观察。新增分支契约负例；该行为变化必须三版本完整回归和最终whole-staged复审，不推partial PASS。
