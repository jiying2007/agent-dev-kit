# CMake 示例超时的可判定诊断

## 目标与依据

PR #278 的 run 43892815480 两次完整回归均为101/102。首次最后命令为CTest，第二次为build；异常后回放的GitHub行时间不能说明阶段耗时。根因未知。本变更为下一次失败保留可区分的阶段时间和本次自有进程组状态。

## 边界

仅修改测试fixture及其确定性回归；不改ADC、发布Skill命令、15秒工作预算、1秒清理预算、失败判据或skip策略。不增加依赖、周期任务或外部模型调用。观察成功只表示该次执行通过，不能反推历史故障根因。

## 验收

1. fixture的原样命令保留时间戳与实际编译命令，普通成功/非零退出语义不变。
2. 超时仍失败、只终止自有进程组；诊断只记录自有进程的非敏感状态，排除参数、环境、其他组，受数量和时间限制。
3. 实际慢子进程证明原超时/清理合同仍有效；进程消失或procfs不可用不遮蔽原始失败。
4. 新CI保留原失败与后续观察；仅精确候选全部必需检查通过才推进合并。
