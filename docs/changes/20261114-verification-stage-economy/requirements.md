# Completion verification: stage-aware and evidence-preserving

- Split checkpoint and goal-final, independently classify low/medium/high risk.
- A small checkpoint uses only affected checks and open dependencies, never closes the parent Goal or grants commit/merge/release authority.
- High-risk checkpoint retains lifecycle, permission, UI, model/trace, runtime and release checks regardless of the shorter report.
- Defer full evidence field template to the existing governance reference, preserve source provenance and immutable review / verification gates.
- Add source-only positive/negative scenarios; real host behavior, billed tokens and latency remain not-measured.
- No new Skill, Agent, Workflow, plugin, scheduler or paid Codex/Work task.
