# 文档写作质量与证据保真（ADK 维护参考）

此文件不是新的 Skill、路由引擎或每次请求都加载的常驻 Prompt。专业内容由 ADR/RCA/需求/交接等原有 Skill 决定；`adk-prose-revision` 只作为显式安装后的成稿优化能力。

## 深度按风险
- **lite / brief**：局部、可逆、面向阅读者的摘要，保留目标、事实、决定、约束、证据及下一步，不填无关表格。
- **standard**：存在真实备选、多人依赖或长期维护影响，解释取舍、影响和可验证的验收。
- **deep / formal / promotion**：公共接口、设备、生产、权限、数据迁移或持久指导规则，需要保留授权、兼容、证据、失败恢复和责任。不能因省 Token 降级。

## 核心原则
1. 先清楚回答读者需要做什么判断，不为了模板凑多个方案、加权评分、5-Why 层数、三方签收或固定任务数。
2. 分离已核实的事实、合理假设与未知。不编造数字、成本、路径、owner、事件、来源、审批及测试结果。
3. 保留术语、单位、限定词（可能/通常/必须）、原始证据链接、否定与因果，不为自然度改变含义。
4. 文稿检查/润色仅在明确要求且有显式能力时按需开展，不强制所有文档多轮确认或重复润色。
5. 完成前按任务风险核验事实保真、技术准确、证据与真实权限。高风险门禁不能被语言质量规则取代。

## 评估
真实改善必须在同模型、同材料、同预算下比较事实遗漏、误编证据、人工编辑量、读者理解、耗时及 Token。静态代码检查、字节减少和场景清单不是实际模型评测；缺真实对照则标 `not-measured`。文档输出格式由现有工具负责，不另建 Word/PDF 引擎。
