# 编排模式参考

> 来源: agent-skills PR #86 + codex-cookbook 军师技能精简

## 认可模式（5 种）

### 1. 直接调用
最简模式。用户意图 → 匹配 skill → 直接执行。

### 2. 单 persona 命令
一个角色负责完整流程。适用于任务边界清晰、无跨角色依赖的场景。

### 3. 并行扇出 + 合并
多个独立子任务并行执行，结果汇总。适用于信息收集、多维度分析。

### 4. 用户驱动顺序流水线
用户控制每一步的推进。适用于需要人工判断的决策流程。

### 5. 研究隔离
独立 agent 做探索性工作，主流程继续。适用于不确定路径的调研。

## 反模式（4 种）

### ❌ Router persona
用一个 agent 做路由分发，再调其他 agent。增加延迟，路由逻辑应内置。

### ❌ Persona 调用 persona
agent 间嵌套调用。调试困难，职责不清。

### ❌ 顺序编排器转述
编排器逐个调用 agent 并转述结果。应改为直接传递上下文。

### ❌ 深层 persona 树
超过 2 层的 agent 嵌套。维护成本指数增长。

## 决策原则

1. **默认不编排** — 轻量优先，只有真正需要时才启动多 agent
2. **最少角色数** — 能 1 个角色解决就不用 2 个
3. **角色精简** — 定期审查角色职责，合并重叠角色
4. **默认偏好表** — 什么意图 → 什么 skill/角色，必须有明确映射

## 技术债处理原则

发现技术债时：
- **阻塞正确性/稳定性** → 立即处理
- **不阻塞最小可交付** → 挂账记录，继续主线
- 模板: `技术债: [描述] | 影响: [范围] | 优先级: [P0/P1/P2]`
