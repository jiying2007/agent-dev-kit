# 规则目录结构

> 来源: VibeFlow 子仓吸收 (2026-05-12)
> 目录版本: 1.0.0

## 概述

本目录定义了 adk 的分层规则结构，避免全局规则污染，支持规则的版本化和可维护性。

## 目录结构

```
rules/
├── README.md                 # 本文件
├── 00-global.md             # 全局规则
├── coding/                  # 编码规则
│   ├── 00-general.md        # 通用编码规则
│   ├── 01-shell.md          # Shell 脚本规则
│   ├── 02-python.md         # Python 规则
│   ├── 03-c.md              # C 语言规则
│   └── 04-cpp.md            # C++ 规则
├── workflow/                # 工作流规则
│   ├── 00-lifecycle.md      # 生命周期规则
│   ├── 01-gates.md          # 门禁规则
│   └── 02-tasks.md          # 任务管理规则
├── quality/                 # 质量规则
│   ├── 00-testing.md        # 测试规则
│   ├── 01-review.md         # 评审规则
│   └── 02-documentation.md  # 文档规则
└── security/                # 安全规则
    ├── 00-general.md        # 通用安全规则
    └── 01-embedded.md       # 嵌入式安全规则
```

## 规则层级

### 1. 全局规则 (00-global.md)

适用范围: 所有语言、所有层次、所有阶段

核心原则:
- 优化可读性、正确性和安全变更
- 最小变更原则
- 显式优于隐式
- 保持模块内聚
- 避免过度抽象

### 2. 编码规则 (coding/)

适用范围: 特定语言的编码规范

分类:
- 通用编码规则: 适用于所有语言
- Shell 脚本规则: Shell 脚本规范
- Python 规则: Python 编码规范
- C 语言规则: C 语言编码规范
- C++ 规则: C++ 编码规范

### 3. 工作流规则 (workflow/)

适用范围: 工作流相关操作

分类:
- 生命周期规则: 8 阶段生命周期规范
- 门禁规则: Gate 机制规范
- 任务管理规则: 合同化任务管理规范

### 4. 质量规则 (quality/)

适用范围: 质量保障相关

分类:
- 测试规则: 测试编写和执行规范
- 评审规则: 代码评审规范
- 文档规则: 文档编写规范

### 5. 安全规则 (security/)

适用范围: 安全相关

分类:
- 通用安全规则: 适用于所有场景
- 嵌入式安全规则: 嵌入式系统特有安全规范

### 规则 ID 命名规范

- 格式: `<类别>-<序号>-<简短描述>`
- 示例: `coding-001-shell-set-e`
- 类别: coding, workflow, quality, security

## 规则使用

### 规则加载

1. **全局规则**: 始终加载
2. **语言规则**: 根据项目语言加载
3. **工作流规则**: 根据工作流阶段加载
4. **质量规则**: 根据质量要求加载
5. **安全规则**: 根据安全要求加载

### 规则检查

```bash
# 检查所有规则
adk rules check

# 检查特定语言规则
adk rules check --language shell

# 检查特定阶段规则
adk rules check --stage build

# 检查特定文件
adk rules check --file scripts/test.sh
```

### 规则验证

```bash
# 验证规则格式
adk rules validate

# 验证规则覆盖
adk rules coverage

# 验证规则冲突
adk rules conflicts
```

## 规则管理

### 添加规则

1. 确定规则类别
2. 确定规则层级
3. 编写规则文件
4. 验证规则格式
5. 测试规则检查

### 修改规则

1. 评估影响范围
2. 修改规则文件
3. 验证规则格式
4. 测试规则检查
5. 更新相关文档

### 删除规则

1. 评估影响范围
2. 确认无依赖
3. 删除规则文件
4. 更新相关文档

## 规则最佳实践

### 1. 规则粒度

- 单个规则只约束一件事
- 规则描述清晰明确
- 规则可独立验证

### 2. 规则层级

- 全局规则保持通用
- 语言规则保持具体
- 避免规则重叠

### 3. 规则维护

- 定期回顾规则
- 及时更新过时规则
- 积累规则经验

### 4. 规则文档

- 规则有清晰描述
- 规则有示例
- 规则有检查命令
