# 紧急工作流模板

> 来源: 企业级AI团队研发规范 (2026-05-13)
> 适用场景: 热修复、线上事故

## 概述

紧急工作流用于处理线上问题，核心原则是"先止血，后复盘"。

## 流程

```
问题定位 → 快速修复 → 验证 → 发布 → 补文档
```

## 阶段详情

### 1. 问题定位

**目标**: 快速定位问题根因

**输入**:
- 问题描述
- 错误日志
- 监控数据

**输出**:
- 根因分析
- 影响范围

**时间**: < 30 分钟

### 2. 快速修复

**目标**: 最小化修复问题

**输入**:
- 根因分析
- 影响范围

**输出**:
- 修复代码
- 修复说明

**原则**:
- 最小化变更
- 不引入新功能
- 不重构代码

**时间**: < 1 小时

### 3. 验证

**目标**: 验证修复有效

**输入**:
- 修复代码
- 测试用例

**输出**:
- 验证结果

**原则**:
- 快速验证
- 重点验证修复点
- 不要求完整测试

**时间**: < 30 分钟

### 4. 发布

**目标**: 快速发布修复

**输入**:
- 修复代码
- 验证结果

**输出**:
- 发布版本

**原则**:
- 快速发布
- 最小化审批
- 记录发布信息

**时间**: < 30 分钟

### 5. 补文档

**目标**: 事后补充文档

**输入**:
- 修复代码
- 发布版本

**输出**:
- 问题报告
- 修复报告
- 复盘报告

**原则**:
- 事后补文档
- 记录经验教训
- 更新知识库

**时间**: < 1 天

## 产物清单

| 产物 | 必需 | 说明 |
|------|------|------|
| 问题报告 | 是 | 问题描述、根因分析 |
| 修复代码 | 是 | 最小化变更 |
| 验证结果 | 是 | 快速验证 |
| 发布记录 | 是 | 发布版本、时间 |
| 复盘报告 | 否 | 事后补充 |

## 与标准流程的区别

| 维度 | 紧急流程 | 标准流程 |
|------|----------|----------|
| 时间 | < 2 小时 | > 1 天 |
| 文档 | 最小化 | 完整 |
| 测试 | 快速验证 | 完整测试 |
| 审查 | 可选 | 必需 |
| 复盘 | 事后补充 | 内置流程 |

## 使用方式

```bash
# 启动紧急流程
adk workflow start --emergency --feature <name>

# 查看紧急流程状态
adk workflow status --emergency --feature <name>

# 完成紧急流程
adk workflow complete --emergency --feature <name>
```
