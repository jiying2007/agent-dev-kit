# 合同化任务清单

> 来源: VibeFlow 子仓吸收 (2026-05-12)
> 模板版本: 1.0.0

## 概述

本文档定义了合同化的任务管理方式，每个任务都有明确的输入、输出和验收标准。

## 任务格式

### 任务定义

```markdown
## Task-<ID>: <任务标题>

### 基本信息

- **ID**: TASK-<YYYYMMDD>-<序号>
- **优先级**: P0/P1/P2/P3
- **预估时间**: <X>h
- **负责人**: <name>
- **状态**: pending/in_progress/completed/blocked

### 输入

- [ ] <输入1>: <描述>
- [ ] <输入2>: <描述>

### 输出

- [ ] <输出1>: <描述>
- [ ] <输出2>: <描述>

### 验收标准

- [ ] <标准1>: <描述>
- [ ] <标准2>: <描述>

### 实现步骤

1. <步骤1>
2. <步骤2>
3. <步骤3>

### 依赖

- 前置任务: TASK-<ID>
- 外部依赖: <描述>

### 风险

- <风险1>: <缓解措施>
- <风险2>: <缓解措施>

### 备注

<其他说明>
```

## 任务状态

| 状态 | 说明 | 转换条件 |
|------|------|----------|
| `pending` | 待开始 | 初始化 |
| `in_progress` | 进行中 | 开始执行 |
| `completed` | 已完成 | 验收标准全部满足 |
| `blocked` | 阻塞 | 依赖未满足或遇到问题 |

## 任务管理原则

### 1. 单一职责

每个任务只做一件事，职责清晰。

### 2. 可验证

每个任务都有明确的验收标准，可独立验证。

### 3. 可追溯

每个任务都有唯一 ID，可追溯到需求和设计。

### 4. 可度量

每个任务都有预估时间，可度量进度。

### 5. 可并行

无依赖的任务可并行执行。

## 最佳实践

### 1. 任务粒度

- 单个任务时间控制在 2-4 小时
- 超过 4 小时的任务应拆分
- 少于 1 小时的任务可合并

### 2. 验收标准

- 使用 SMART 原则（具体、可衡量、可达成、相关、有时限）
- 每个任务至少 3 个验收标准
- 验收标准应可自动化验证

### 3. 依赖管理

- 明确标注前置任务
- 避免循环依赖
- 无依赖任务可并行执行

### 4. 风险管理

- 识别潜在风险
- 制定缓解措施
- 定期评估风险

### 5. 进度跟踪

- 每日更新任务状态
- 记录阻塞问题
- 及时调整计划

## 工具支持

### 任务管理命令

```bash
# 创建任务清单
adk tasks create --feature user-login

# 查看任务清单
adk tasks list --feature user-login

# 更新任务状态
adk tasks update --feature user-login --task TASK-20260512-001 --status in_progress

# 查看任务依赖
adk tasks deps --feature user-login --task TASK-20260512-003

# 生成进度报告
adk tasks report --feature user-login
```
