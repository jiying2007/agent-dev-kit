# Growth evidence and privacy (on demand)

Read only for explicit cross-project or full-history growth reviews. Default local evidence reads should be bounded to user-provided scope.

## Data access
- Prefer manifests/indexes, commit summaries, test results, issue conclusions and archived sanitized notes.
- Read `$CODEX_HOME/history.jsonl`, `~/.codex/history.jsonl`, memories or other project directories only when authorized, necessary and available. Never infer automatic access.
- Preserve privacy: avoid copying raw chat, keys, tokens, customer data, paths exposing personal details, credentials, or unrelated employee records.
- Report `read_scope`, `source_refs`, `redaction_status`, `unknowns`, and `external_actions`.

## Bounded output
- Confirmed recurring patterns require evidence across time/tasks; one-off errors are not a stable person-level attribute.
- A recommendation needs evidence, action, and observable signal; if the data supports only one recommendation, give one.
- Longer report / personalized study plan / external learning resources only on explicit request.
- Any memory/AGENTS/Skill promotion remains candidate-only and requires owner review, `trace-feedback-eval-handoff` and actual validation. No silent storage or provider calls.
