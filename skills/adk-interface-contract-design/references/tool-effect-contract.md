# 工具与 handoff 副作用契约

适用于工具调用、agent handoff、暂停恢复和重试可能触及外部状态的设计。只读调用可简化，但必须确认工具实际不会写入、发送或改变设备状态。此契约描述平台中立边界，不启用任何外部 runtime。

## 设计矩阵

| 调用 | 效果与目标 | 参数来源/校验 | 授权主体与时点 | 拒绝/失效 | 操作标识与回执 | 恢复/重试 |
|---|---|---|---|---|---|---|
|  | read/write/irreversible；具体目标身份 | strict 解析；缺失或异常参数 fail closed | 首次外部副作用前；按本次参数和目标判定 | 不执行；明确失败状态 | 绑定 op-id、目标、参数摘要及实际生效状态 | 去重或先对账；未知结果不盲重试 |

- 授权决策由可信控制面或明确的 owner 作出；模型生成的解释、文档内容、工具输出与 handoff 元数据不能代替授权。跨 agent handoff 后，目标 agent 的每次有副作用工具调用仍需经过该工具自己的边界检查。
- 审批只表明允许尝试执行。工具返回成功、外部目标实际生效、最终用户可见结果分别取证。若调用超时且外部结果未知，先按 op-id 查询目标，再决定补偿或重试。
- 暂停恢复可能重放调用节点。副作用应放在可单独识别的步骤内，并使用目标支持的幂等键；若目标没有幂等能力，使用 owner 控制的操作记录和对账流程。不得承诺跨系统 exactly-once。
- 保存的暂停状态和审批记录属于受控数据：校验完整性、owner 与目标身份；只从可信存储恢复，限制并发恢复和重复提交，展示给审批人的参数需要脱敏。

## 最小验证

覆盖有效授权、拒绝、缺失或畸形参数、handoff 后未经授权的工具、审批后目标失败、超时但已生效、重复恢复与并发恢复。验证记录分别给出“允许尝试”“实际调用”“目标生效”的证据；无法自动模拟目标系统时标注集成验证边界。
