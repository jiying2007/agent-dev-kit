# adk-lightweight-planning

## Goal
用户只想先看计划时，输出最短、可执行且可验证的路径，不代替实际执行、Goal/Loop 或权限审批。

## Workflow
1. 只读查询与任务直接相关的入口、约束和已有测试，不进行无目标的全仓扫描。
2. 根据任务大小写必要的动作：小修 2–3 项亦可，大任务按真实依赖拆分，**不强制 4–10 项**，不凭空增加“先调研、再讨论”。
3. 每一项绑定可观察结果与真实验证信号。路径、命令、资源预算无法核实时标 TBD，不编造执行或测试成功。
4. 缺失关键事实决定方案时只提必要问题，其他可逆假设注明；高风险仍明确授权、回退与隔离条件。
5. 用户要求落地时退出本只读 Skill，转交实际实施流程；不自动开启定时巡检或付费模型调用。

## Output
`Goal / Scope / Concrete Actions / Verification / Only Blocking Unknowns`

## Quality Gate
- 只读不进行外部写、提交、删除或部署；计划中的步骤必须清晰可检查。
- 高风险验证与恢复边界不会因为篇幅变短而省略。
- 文档保真：不改变需求事实、日期、单位或测试结论；静态缩短不等于实际 Token 节省。
