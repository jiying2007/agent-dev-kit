# 纪律化调试循环

## Goal
- 通过纪律化调试循环进行系统性根因分析，避免猜测性修改。

## Prerequisites
- 确认错误信息/异常现象可复现。
- 获取最小上下文：错误日志、复现步骤、相关代码。

## 核心流程

1. **复现**: 确认问题可稳定复现
2. **定位**: 缩小问题范围（二分法/日志/断点）
3. **根因**: 识别根本原因（不是表面症状）
4. **修复**: 最小变更修复根因
5. **防护**: 添加测试防止回归

## 10 种反馈回路

1. 运行测试 → 看输出
2. 添加日志 → 观察变量
3. 断点调试 → 单步执行
4. 二分注释 → 缩小范围
5. 最小复现 → 隔离问题
6. 对比正常 → 找差异
7. 检查版本 → 排除回归
8. 搜索日志 → 找错误模式
9. 检查依赖 → 排除冲突
10. 回滚代码 → 确认引入点

## Workflow
1. 复现：确认问题可稳定复现
2. 定位：缩小问题范围（二分法/日志/断点）
3. 根因：识别根本原因（不是表面症状）
4. 修复：最小变更修复根因
5. 防护：添加测试防止回归

## 与 systematic-debugging 的区别
- diagnose-loop: 快速诊断循环，适用于多轮假设验证
- systematic-debugging: 结构化调试流程，适用于复杂故障的系统化排查

## Quality Gate
- 问题已复现并定位根因
- 修复已通过测试验证
- 回归测试已添加

## 合理化借口拦截

| 借口 | 现实 | 正确做法 |
|------|------|---------|
| "大概知道问题在哪" | 猜测性修改会引入新 bug | 走完调试循环确认根因 |
| "改一处就好了" | 表面修复可能掩盖根因 | 找到根本原因再修复 |

## 健壮性规范

- **输入验证**: 确认错误信息完整且可复现
- **重试策略**: 调试命令失败时换一种方法
- **超时控制**: 单步调试不超过 30 分钟
- **异常隔离**: 某个调试路径不通立即切换
- **日志记录**: 记录每步操作和结果
