# 上下文工程

## Goal
- 优化 Agent 上下文设置，提高 AI 输出质量和效率。

## Prerequisites
- 确认项目结构和规范文档可访问。
- 获取最小上下文：项目类型、Agent 工具。

## 5 级上下文层次

1. **Rules**: 全局规则（AGENTS.md）
2. **Specs**: 需求规格（SPEC.md）
3. **Source**: 源代码（相关文件）
4. **Errors**: 错误信息（日志/输出）
5. **History**: 历史上下文（之前的对话）

## 上下文优化策略

| 策略 | 说明 | 效果 |
|------|------|------|
| 渐进式披露 | 先给概要，按需深入 | 减少 token 消耗 |
| 结构化输入 | 用表格/列表代替段落 | 提高解析准确度 |
| 关键信息前置 | 最重要的信息放前面 | 确保不被截断 |
| 去除噪音 | 删除无关信息 | 提高信噪比 |

## Workflow
1. 分析项目结构和规范
2. 识别 Agent 需要的上下文层次
3. 按优先级组织上下文（关键信息前置）
4. 应用渐进式披露减少 token 消耗
5. 验证 Agent 输出质量

## Quality Gate
- 上下文文件格式正确
- Agent 输出质量有明显提升
- 无信息过载

## Evidence Template
```md
- 上下文层次: <levels used>
- Agent 输出质量: pass / needs-fix
- Token 消耗变化: before N -> after M
```

## 合理化借口拦截

| 借口 | 现实 | 正确做法 |
|------|------|---------|
| "上下文已经够了" | Agent 输出质量下降是信号 | 检查并补充缺失上下文 |
| "全给 Agent 看就好" | 信息过载会降低质量 | 用渐进式披露 |

## 健壮性规范

- **输入验证**: 检查上下文文件格式正确
- **重试策略**: Agent 输出不佳时补充上下文重试
- **超时控制**: 上下文准备不超过 10 分钟
- **异常隔离**: 单个上下文文件缺失不影响整体
- **日志记录**: 记录提供了哪些上下文
